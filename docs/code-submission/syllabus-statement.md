## Part 1: Syllabus statement (paste into the syllabus)

### Artificial Intelligence (AI) in [COURSE CODE AND TITLE]

**What counts as AI in this course.** In this course, *AI* means any tool that generates or completes code, text or explanations for you. Examples include chatbots, AI coding assistants, code-completion tools beyond the editor's basic autocomplete, and AI agents. A compiler, a debugger and the Java documentation are not AI.

**Default rule: restricted.** You may use AI **only** where an assignment explicitly allows it, and only in the way that assignment describes. If an assignment says nothing, AI is **not** allowed. Every assignment shows one of three levels:

| Level | What it means | Example |
|---|---|---|
| **Forbidden** | No AI use of any kind. | Exams, in-class coding checks, typing-skills exercises. |
| **Restricted** (default) | AI allowed only for the purposes the assignment lists. Writing or completing your solution code with AI is not allowed. | Asking an approved AI tool to explain a compiler error, then fixing the code yourself. |
| **Permitted** | AI allowed for any part of the work, as long as you disclose it. | A project where you compare your design with an AI-suggested design. |

**Disclosure.** When you use AI on an assignment that allows it, complete the *AI use disclosure* in the Code Submission editor. State the tool, what you used it for, and how much it contributed (minimal, moderate or extensive). You are fully responsible for every line you submit, including any AI-assisted work. Using AI to produce work you submit as your own without permission or attribution is plagiarism. Using an AI agent to complete an assessment without your own interaction is cheating (AI Policy §VI.C).

**Process-tracking software.** Coding work in this course is written and submitted in the **Code Submission editor**, which is process-tracking software as defined by the University's AI policy. Using it is required for [ALL CODING ASSIGNMENTS / LISTED ASSIGNMENTS]. Inside the editor only, it records:

- your edits as you type, including deletions and undo
- when you paste, copy or cut text, and how much
- when you run or compile your code, and the results
- when the editor window loses or regains focus

It does **not** record anything outside the editor: no other browser tabs or their content, no other applications, no camera, no microphone and no screen capture.

**Why.** The record lets me see *how* you solved a problem, not only the final answer. I use it to find where students get stuck and to help you, to give credit for your process, and to support academic integrity.

**Privacy.** These records are confidential education records protected by FERPA and handled as Class I - Confidential data under the University's Data Stewardship and Classification Standard. Only I [AND AUTHORIZED TEACHING ASSISTANTS] can view them. You may request to see your own record. Records are kept and destroyed according to the University's Records Retention Policy.

**Concerns.** The editor can highlight patterns such as large pastes. A highlight is **not** an accusation; it is a reason for a conversation. If I have a concern about academic integrity, I will first talk with you. Any formal concern follows the University's Academic Dishonesty Policy and Student Code of Conduct, with the Office of Student Conduct as the point of contact.

**Accessibility.** If you use dictation, switch access or other assistive input, contact [STUDENT ACCESSIBILITY RESOURCE CENTER CONTACT] and let me know. I will adjust the editor so your input method is not flagged.

**Your responsibilities.** Complete the University's required AI training, follow each assignment's AI level, and ask me if you are unsure whether a use is allowed. Consequences for violating this policy: [COURSE-SPECIFIC CONSEQUENCES, e.g. zero on the assignment and referral under the Academic Dishonesty Policy].
